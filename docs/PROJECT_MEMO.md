# 项目备忘录

## 记录格式

每条备忘按以下格式维护：

- 状态：`待讨论` / `已确认` / `进行中` / `已完成` / `延后`
- 优先级：`P0` 立即影响核心体验，`P1` 近期体验完整性，`P2` 中期增强，`P3` 长期想法
- 所属页面：现在就听 / 播放页 / 资料库 / 创作 / 我的 / 全局 / 后端
- 核心需求：一句话说明用户真正想完成什么
- 初步方案：当前倾向方案，后续可以更新
- 验收要点：完成后回头检查什么

## 近期已确认但未全部完成

### 播放与详情体验闭环

- 状态：已确认
- 优先级：P0
- 所属页面：播放页 / 歌单 / 专辑 / 全局菜单
- 核心需求：用户听到一首歌后，可以顺手分享、收藏、加入歌单或专辑，并且菜单文案不产生误解。
- 初步方案：复用 `UniversalContextMenu`、`CollectionCreatableSelect`、`attachUploadedSongToCollection`，不要为播放页单独重写一套加入合集流程。
- 验收要点：播放页更多菜单能加入歌单/专辑；合集菜单文案显示“置顶此歌单”“删除此专辑”等对象语义；播放器底部仍保持评论、记忆卡片、待播清单三按钮。

### 现在就听页面结构整理

- 状态：已确认
- 优先级：P0
- 所属页面：现在就听
- 核心需求：首页应该帮助用户快速继续听歌，并发现最新公开内容，而不是堆重复的大封面模块。
- 初步方案：删除“为你打开”和“我的最近上传”；第一栏改为高效率的“最近播放/继续收听”模块；“最新公开”保持大封面横滑；未来排行榜只放轻量入口。
- 验收要点：标题和其他页面视觉对齐；最近播放不再是大封面列表；最新公开仍保留聚焦大封面。

### 加载骨架屏与等待反馈

- 状态：已确认
- 优先级：P1
- 所属页面：播放页 / 歌单 / 专辑 / 评论区 / 创作 / 我的
- 核心需求：加载、保存、加入、评论发送时，用户能看到和真实布局一致的等待反馈。
- 初步方案：抽可复用骨架组件，例如封面骨架、歌曲行骨架、合集头部骨架、评论行骨架；成功反馈优先用 toast 或 inline feedback，逐步减少 `alert`。
- 验收要点：等待时不空白、不跳动、不重复提交；骨架尺寸贴近真实 UI。

## 之后回头做的增强项

### 个人听歌排行

- 状态：待讨论
- 优先级：P2
- 所属页面：我的 / 现在就听
- 核心需求：用户想知道自己哪些歌听得最多，并能快速回到高频内容。
- 初步方案：完整排行放在“我的”页的“听歌统计”；现在就听只放前 3-5 首的轻量入口。
- 验收要点：支持本周、本月、全部时间；只统计当前用户播放记录；私有歌曲只对本人显示。

### 全站排行榜

- 状态：待讨论
- 优先级：P2
- 所属页面：资料库
- 核心需求：小范围用户想看到全站公开内容中哪些歌曲被播放最多。
- 初步方案：资料库新增“排行榜”分段，基于公开歌曲统计；不让私有歌曲进入公共榜。
- 验收要点：公开榜不泄露私有内容；排行口径明确，例如播放量、收藏数、评论数。

### 创作者统计

- 状态：待讨论
- 优先级：P2
- 所属页面：创作
- 核心需求：用户想知道自己上传的作品被播放、收藏、评论了多少。
- 初步方案：创作页新增“作品表现”区，展示我上传歌曲的播放排行、收藏数、评论数。
- 验收要点：只统计自己上传或自己拥有的内容；与“我的听歌排行”区分开。

### MV 支持

- 状态：延后
- 优先级：P3
- 所属页面：播放页 / 上传流程
- 核心需求：歌曲可以关联用户自行上传的 mp4 等 MV 文件。
- 初步方案：先为歌曲增加可选视频资源字段，再在播放详情页提供 MV 入口；不做联网 MV 获取。
- 验收要点：无 MV 时不显示入口；有 MV 时可打开播放；移动端全屏体验正常。

### 歌词体验

- 状态：延后
- 优先级：P3
- 所属页面：播放页 / 歌词页
- 核心需求：支持用户提供的歌词文件或歌曲内嵌歌词，并呈现接近 Apple Music 的动效。
- 初步方案：先支持本地/上传歌词解析，再评估 Lyricify-Lyrics-Helper、LyricSphere、amll-web、BetterLyrics 的可借鉴部分。
- 验收要点：不依赖联网歌词；无歌词时有优雅空状态；有歌词时能跟随播放进度。

### 分享系统深化

- 状态：待讨论
- 优先级：P2
- 所属页面：全局菜单 / 评论区 / 播放页
- 核心需求：歌曲、评论、记忆卡片等内容可以通过系统分享或复制链接分享。
- 初步方案：先统一歌曲分享，再扩展评论和记忆卡片；优先使用 `navigator.share`，降级复制文本。
- 验收要点：移动端系统分享可用；桌面端复制内容明确；私有内容不生成公共可访问链接。

### 鸿蒙字体与设备适配

- 状态：待讨论
- 优先级：P2
- 所属页面：全局
- 核心需求：在鸿蒙和国产安卓环境中字体显示更接近系统原生。
- 初步方案：全局字体栈加入 HarmonyOS Sans 相关 fallback，同时保持 iOS / macOS 使用系统字体。
- 验收要点：标题、按钮、列表文本不溢出；不同设备字体重量观感一致。

### 共享元素转场

- 状态：待讨论
- 优先级：P2
- 所属页面：现在就听 / 资料库 / 歌单 / 播放页
- 核心需求：从封面进入播放页或详情页时有更自然的视觉连续性。
- 初步方案：先在封面到播放详情页做局部共享元素效果，避免全站一次性重构。
- 验收要点：转场不影响播放状态；低性能设备可以降级为淡入淡出。

## 页面边界备忘

- 现在就听：快速继续听、发现最新公开、轻量排行入口。
- 资料库：浏览当前用户可见内容，包括歌曲、专辑、歌单，未来承载全站排行榜。
- 创作：上传、草稿、我的上传、作品表现统计。
- 我的：个人资料、收藏、个人听歌统计、个人展示。
- 播放页：沉浸播放、收藏、评论、记忆卡片、待播清单、更多管理动作。
