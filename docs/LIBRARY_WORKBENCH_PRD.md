# 资料库与创作工作台重构 PRD

## 背景

当前项目已经形成四个核心入口：现在就听、资料库、上传、我的。代码层面显示，资料库已经内置了上传入口（`UploadModal`），底部的上传页也保留了一套完整上传流程（`Upload.tsx`），两者存在明显重复。

从真实数据权限看，歌曲池的语义已经基本成立：普通登录用户能看到公开歌曲和自己的私有歌曲。资料库因此应定位为“可见内容浏览”，而不是只看自己的本地管理页。上传页则更适合升级为“创作工作台”，承担个人内容生产、草稿、编辑和管理。

## 产品目标

- 明确四个核心页面边界，避免资料库、上传页、我的页互相抢职责。
- 将上传流程统一成同一套组件，资料库快捷上传与创作工作台上传使用同一个能力源。
- 以 Apple Music / Apple Design 为主要体验指导：内容优先、低干扰、毛玻璃层次、克制动效、明确触达区。
- 保留个人小范围使用的轻量感，不引入商业化、运营化、复杂审核等重系统。

## 非目标

- 不做商业化、付费、版权审核、运营后台。
- 不把资料库改成社交广场。
- 不在本阶段重做完整播放内核。
- 不在未讨论视觉方向前大幅改写资料库画布视图。

## 当前事实

- `App.tsx` 底部四个 Tab 是 `home / library / upload / profile`。
- `pages/Library.tsx` 展示全局 `songs`，并通过加号菜单打开 `UploadModal`。
- `pages/Upload.tsx` 同时包含上传流程和“我的上传”列表。
- `pages/Profile.tsx` 根据 `ownerId === targetUserId` 展示个人收录，并展示专辑、歌单、收藏。
- `supabaseApi.fetchSongs()` 不在前端手动过滤公开/私有，而是依赖 Supabase RLS 返回可见歌曲。
- 实测歌曲权限：测试账号可见歌曲 9 首，自己的 7 首，别人的 2 首，没有返回非本人私有歌曲。
- 实测合集权限：测试账号能看到一个非本人 `private` playlist，原因是 `albums.visibility` 与旧字段 `albums.is_public` 策略存在不一致。

## 页面边界

### 现在就听

定位：打开应用后的“开始听”入口。

应承担：
- 继续播放、最近播放、常听内容。
- 基于可见歌曲池的轻推荐。
- 新上传/新公开内容的低干扰展示。

不承担：
- 上传管理。
- 歌曲编辑。
- 复杂资料库筛选。

### 资料库

定位：浏览当前用户可见的全部内容。

应承担：
- 全部可见歌曲：公开歌曲 + 自己私有歌曲。
- 搜索、筛选、排序。
- 歌曲、专辑、歌单之间的浏览切换。
- 列表视图和画布视图。
- 快捷创建入口：上传音乐、新建专辑、新建歌单。

不承担：
- 长表单上传工作流的主要承载。
- 个人主页装饰设置。

### 创作工作台

定位：管理“我生产或收录的内容”。

应承担：
- 上传草稿恢复。
- 音频选择、预览、裁剪、封面、元数据。
- 公开/私有设置。
- 加入已有专辑/歌单，或上传时新建专辑/歌单。
- 我的上传列表：编辑、删除、公开/私有、置顶、播放数据。
- 未来支持专辑制作流程。

不承担：
- 全站内容浏览。
- 对外个人展示。

命名建议：底部 Tab 从“上传”改为“创作”或“工作台”。推荐“创作”，更短，更符合 Apple Music 的内容生产语义。

### 我的

定位：身份、资料与对外展示。

应承担：
- 个人资料、头像、封面、头像框、状态。
- 对外展示收录、专辑、歌单。
- 收藏列表。
- 账号设置入口。

不承担：
- 上传表单主流程。
- 全站资料库筛选。

## 上传能力统一方案

推荐抽象为三层：

- `UploadDraftProvider`：管理草稿、文件、封面、裁剪区间、保存状态。
- `UploadEditor`：纯 UI 表单，负责文件选择、波形裁剪、元数据、公开/私有、合集选择。
- `UploadEntrySurface`：决定呈现方式。资料库中是 Modal，创作工作台中是页面区块。

这样资料库和创作工作台可以共享核心逻辑，但保留不同入口体验。

## 资料库重构方向

先做“信息架构”和列表体验，再做画布视觉升级。

推荐结构：
- 顶部：标题、搜索、创建按钮。
- 分段控制：歌曲 / 专辑 / 歌单 / 收藏。
- 内容筛选：全部、我的、公开、私有、最近、置顶。
- 列表项：封面、标题、艺人/专辑、公开状态、播放状态、更多菜单。
- 空状态：直接给出下一步动作，例如“上传音乐”或“去现在就听”。

Apple Design 约束：
- 不堆卡片，不做营销式 hero。
- 列表密度要高，但留足触控区。
- 图标按钮有 `aria-label`，触达区至少 44px。
- 毛玻璃用于浮层和导航，不用于每一个列表项。
- 动效使用 150-300ms，优先 opacity/transform。

## 验收标准

- [ ] 四个 Tab 的文案与职责一致，不再让用户误解“上传页只是单按钮入口”。
- [ ] 资料库和创作工作台使用同一套上传核心组件。
- [ ] 上传草稿在 Modal 和工作台之间一致恢复。
- [ ] 我的上传只展示当前用户内容。
- [ ] 资料库展示当前用户可见内容，不误露非本人私有歌曲/合集。
- [ ] 新建/编辑合集后，公开/私有状态在列表、详情、个人页一致。
- [ ] `npm run check` 通过。
- [ ] 使用测试账号跑 `npm run smoke:auth` 通过。
