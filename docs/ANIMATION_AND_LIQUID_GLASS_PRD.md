# JZone 动效与液态玻璃体验 PRD

## 1. 文档目的

本 PRD 将前期讨论的五批动效和 F 方案液态玻璃材质收敛为一套可长期维护的体验规范。目标不是让所有元素持续运动，而是用少量高价值动画解释对象关系、状态变化和页面层级。

适用范围：现在就听、资料库、创作、个人页、合集详情、全屏播放页、Mini 播放器、Mini 菜单及通用弹窗。

## 2. 产品目标

- 以 Apple / Apple Music 的内容优先原则建立统一、克制、可预测的动效语言。
- 用共享元素解释“同一个对象去了哪里”，减少页面切换的割裂感。
- 用 F 方案统一需要悬浮于内容上方的玻璃材质，普通内容卡片不滥用玻璃。
- 液态玻璃只承担材质和层级表达，不为普通控件增加果冻拖拽或液滴融合手势。
- 以 60 FPS 为目标，优先保证中端手机、鸿蒙 Android 兼容层和 Chromium 浏览器的稳定性。

## 3. 非目标

- 不追求逐像素复刻 iOS 系统合成器。Web 无法可靠读取和重新合成任意跨层背景，采用视觉与交互等价实现。
- 不把每个按钮、卡片和列表项都改成液态玻璃。
- 不在本阶段重做 Bento 视图、歌词引擎、播放内核或业务数据模型。
- 不为了动效引入持续截图 DOM、逐帧 Canvas 转码或多层嵌套 `backdrop-filter`。

## 4. 设计原则

### 4.1 对象连续性

同一歌曲、封面、头像或合集跨页面时优先使用共享元素，而不是让旧页面消失、新页面重新出现。

### 4.2 状态先于装饰

动画必须回答至少一个问题：对象去了哪里、操作是否成功、当前状态是什么、下一步能做什么。不能回答时不增加动画。

### 4.3 主次明确

一个视图同时最多存在 1 个主动画和 1 个辅助动画。播放封面展开时，列表卡片、背景和文字不应各自争抢注意力。

### 4.4 可中断与可逆

页面转场、拖拽、菜单移动和播放控制必须允许用户中途反向操作，不锁死交互，不依赖固定延时完成业务逻辑。

### 4.5 减少动态效果

系统启用 `prefers-reduced-motion` 时：禁用共享元素位移动画和大幅缩放；保留 100 至 160ms 的透明度反馈，业务能力不变。

## 5. 统一动效参数

| 场景 | 建议时长 | 曲线 / 弹簧 | 说明 |
| --- | --- | --- | --- |
| 点击与选中 | 100-160ms | ease-out | 颜色、透明度、轻微缩放 |
| 菜单出现 | 680-840ms | `cubic-bezier(.2,.8,.2,1)` | 整块玻璃先建立模糊，再完成 Q 弹形变 |
| 页面切换 | 260-360ms | ease-out | 位移不超过 20px |
| 共享元素 | 360-460ms | `cubic-bezier(.22,.72,.18,1)` | 播放器展开 460ms、收拢 360ms，反向操作从当前帧续接 |

## 6. 五批正式改造

### 第一批：动效地基与性能基线

- 建立 motion tokens、减少动态效果策略和统一转场容器。
- 页面级组件按路由懒加载，避免动效方案继续放大首包。
- 建立浏览器截图、像素、控制台错误和长任务检查。
- 当前进度：页面拆包已完成，入口包由约 503.9 KB 降至约 260.5 KB。

### 第二批：共享元素

- 现在就听右上头像 → 个人页头像。
- 歌曲封面 / Bento 封面 → 全屏播放页封面。
- Mini 播放器 → 全屏播放页。
- 歌单或专辑封面 → 合集详情页。
- 返回时必须沿原路径逆向收拢，并兼容目标元素离屏或已卸载的降级情况。
- 播放器容器从 Mini 的实时 DOMRect 出发，由单一可中断进度值派生四边 `clip-path inset` 和圆角并铺满视窗；封面、歌名、艺人各使用单一 FLIP 进度值且不做透明度交叉淡化，其他控制项在 140ms 后显现。展开为 460ms、收拢为 360ms，用户在动画完成前反复开合时必须从当前几何状态直接反向。
- Mini 播放器 DOM 与 SVG 折射材质在全屏播放页期间持续挂载；全屏稳定态仅通过 `inert` 和 `aria-hidden` 隔离交互，避免关闭末帧先失去模糊/折射再重新生成材质。

### 第三批：导航与布局转换

- 四个核心页面使用低位移淡入淡出，不做整屏夸张推拉。
- 资料库列表与 Bento 切换保留对象连续性；不改变 Bento 内部交互和视觉设计。
- Mini 菜单从一首歌曲切换到另一首歌曲时平移到新锚点，不重复播放完整入场动画。
- 长列表滚动期间暂停非必要装饰动画。

### 第四批：操作反馈

- 收藏、加入歌单或专辑、公开/私有、置顶等动作使用原位状态变更和轻量反馈。
- 上传或向合集加歌时，以歌曲骨架项占位，成功后由真实内容接管位置。
- 删除列表项先确认业务成功，再执行高度收拢；失败时恢复原位置。
- 菜单出现采用“模糊建立 → 尺寸展开 → 内容淡入”，关闭顺序反向。
- 菜单退出总时长约 360ms；内容、材质壳和边缘高光必须同步淡出，不允许内容消失后只剩高光框继续运动。

### 第五批：播放沉浸体验

- 播放/暂停图标使用同一轮廓内的形态转换。
- Mini 播放器、全屏播放页、封面和背景颜色变化保持节奏一致。
- 拖拽进度条必须实时跟手，松手后才提交 seek；不使用延迟追赶动画。
- 歌词动效作为独立后续阶段，不阻塞本轮交付。

## 7. F 液态玻璃材质架构

### 7.1 单一材质层

所有 F 材质通过 `LiquidGlassSurface` 和统一设置参数生成。内容、图标和点击区域位于材质层上方，不再叠加历史毛玻璃、渐变遮罩或第二套 `backdrop-filter`。

### 7.2 Backdrop Root 约束

液态玻璃祖先节点不得使用持续 `filter`、`backdrop-filter`、非必要蒙版或制造独立合成背景的属性。即使 `filter: blur(0)` 也会建立新的 Backdrop Root，使子级只能采样透明祖先而无法读取页面背景。项目实测 `will-change: opacity` 同样会提前建立 Backdrop Root，因此菜单采样根只允许声明位置变化所需的 `will-change: left, top`。

### 7.3 当前适用组件

- 底部 Tab 与活动透镜。
- Mini 菜单与集合选择 Mini 窗。
- 登录卡片。
- Mini 播放器使用与资料库控件一致的 F 材质；宽面板启用平滑的全幅中心透镜折射。纵向 Mini 菜单使用独立 `panel` 位移几何和均衡通道编码，按真实矩形边缘计算法线，避免圆角向中心放射出波浪。

### 7.4 移动端兼容

- 资料库右上控件、Mini 播放器和 Mini 菜单使用 F 实验的 Shuding 位移轮廓，但全部视觉参数统一读取高级设置。
- SVG `feImage` 同时写入 `href` 与 `xlink:href`，兼容较旧 Chromium / WebView 的 SVG 图像绑定。
- 粗指针移动设备增加 2.5px 低成本毛玻璃兜底；SVG 折射可用时继续叠加折射，不可用时也不会退化成纯透明按钮。
- Mini 模态框只让菜单内容执行“模糊淡入 / 模糊淡出”，不模糊整张页面，也不在玻璃祖先上使用 `filter`。
- 液态玻璃中的中性图标通过低频背景亮度采样连续切换黑白；激活 Tab、危险和警告语义色保持固定。
- 禁止使用 `mix-blend-mode` 适配液态玻璃图标，避免 Chromium 破坏 SVG 背景折射。
- 需要缩放和模糊时，F 材质必须保持在静态采样层；整块玻璃通过无 `transform` 的 `top/right/bottom/left` 几何插值完成 Q 弹，内容兄弟层同步执行缩放和模糊，禁止在材质祖先上执行 `transform`、`filter` 或 opacity 合成提升。
- Mini 播放器与底部 Tab 保持 12 至 15px 间隔，当前基准值为 12px；每次修改尺寸后必须重新执行连续切页合成压力测试。

## 8. 性能预算

- 入口 JS 原始体积保持低于 300 KB；新增页面能力继续使用按路由拆包。
- 单个玻璃控件只生成一张位移图；尺寸和参数未变化时不逐帧重建。
- 单次交互不得产生超过 50ms 的长任务；目标设备稳定接近 60 FPS。
- 页面滚动时不运行无限装饰动画；登录流光背景在低性能或减少动态模式下静止降级。

## 9. 验收标准

- Mini 播放器祖先无 `filter`，其背景能明确模糊下方封面和文字。
- Mini 菜单只有一套 F 材质，能采样菜单下方内容并产生可见折射。
- 资料库右上控件不附加长按拖拽手势，移动端至少保持清晰毛玻璃，支持 SVG backdrop URL 时显示 F 折射。
- 页面切换、快速返回、滚动和连续长按不产生控制台错误、内容闪烁或路由阻塞。
- 头像、Mini 播放器封面和合集封面使用稳定对象 ID；连续前进/返回 10 次后不残留共享克隆层，焦点回到来源控件。
- Chromium 桌面和安卓实机通过；鸿蒙兼容层若不支持 SVG backdrop URL，降级为清晰毛玻璃而不是纯透明。
- `prefers-reduced-motion` 下所有核心操作仍可完成。

## 10. 推进策略

先以资料库右上控件作为 F 材质的首个移动端验证点，确认安卓 Edge 与鸿蒙兼容层的折射或降级结果，再按五批任务推进。已放弃液滴控件方案，不再扩展相关手势。
