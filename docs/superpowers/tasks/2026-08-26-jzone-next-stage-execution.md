## 1. COS 历史资源只读扫描、预览报告、小批迁移、费用验证

### 目标

在新上传媒体链路已经稳定的前提下，识别历史高码率音频和重复封面，量化可迁移对象、风险和费用，并在获得用户明确批准后执行可回退的小批迁移，验证节流改造在真实 COS 账单/监控口径下是否生效。

### 前置条件

- 第 0 批已完成；基线回归和手机播放回落证据可查。
- 腾讯云账号和 COS 资源恢复可读，能够读取对象元数据、数据库引用和费用/监控数据；扫描路径使用已批准的内网或临时下载方案。
- 已有明确的候选规则、批次上限、预算阈值、对象保留策略和异常处理方式；任何实际写入仍需单独用户批准。
- 远端备份门已经明确；如果需要数据库快照、COS 版本保护或其他云端保护措施，先走用户批准门。

### 明确不做

- 不在客户端启动、登录、播放或页面打开时自动迁移。
- 不直接全量迁移，不删除源文件，不覆盖已有对象，不修改无关对象，不把孤儿或有歧义对象强行归入候选。
- 不把只读扫描或预览报告当作已经迁移；不把项目端估算当作腾讯云实账。
- 不把腾讯云永久密钥放入前端包，不借本批新增与 COS 无关的设置页、播放器或 Bento 改版。

### 数据/兼容边界

- 原始音频永久保留；只有无损或估算码率超过 `256 kbps` 的候选才可按已完成的新链路提供 `160 kbps` 播放副本，普通 M4A/MP3 保持原流程。
- `stream_audio_path`、`stream_file_size`、`stream_bitrate_kbps` 继续可空；对象验证完成前不得写入这些字段。旧数据和旧客户端仍使用原始媒体或既有回落路径。
- 歌曲和专辑/歌单封面继续使用内容哈希路径；共享封面受删除保护。重复封面只提出候选，不自动删除源对象。
- 所有候选记录保留来源对象、目标对象、引用关系、哈希/元数据、处理状态和失败原因；无法可靠读取或判断的项目进入人工复核，不猜测。
- 费用同时保留“腾讯云实账/监控”和“项目端估算”的口径、时间范围与时区；数据缺失、延迟或过期必须显式标记。

### 实现任务

1. **只读扫描**：读取 COS 和数据库引用，输出历史高码率音频、重复封面、未引用对象、缺失对象、无权限对象和歧义对象清单；扫描不得产生对象或数据库写入。
2. **预览报告**：逐对象列出拟执行动作、源/目标 key、哈希或校验方式、拟写字段、预计新增字节、请求数、费用范围、风险和回滚步骤；报告必须能复现同一候选集。
3. **明确批准**：向用户提交精确的候选数量、对象列表或稳定筛选条件、批次上限、成本上限、保留策略、有效期和回滚方案；未获批准不得进入下一步。
4. **小批执行**：只处理批准范围内的小批对象，采用幂等标识；先生成/复制并验证播放副本，再按批准方案写入可空字段，原始对象保持不动。
5. **费用验证**：在监控和账单可见后，比较迁移前后存储量、外网下行、读请求、估算费用和实际费用，解释时间延迟与口径差异，不用缺失数据补成零。

### 自动验证

- 只读扫描重复运行结果稳定，且可证明没有 COS 对象写入、数据库写入或删除动作。
- 预览模式在无批准时始终为 dry-run；候选规则、字节/费用计算、哈希和状态转换有隔离样本验证。
- 获批小批验证：源对象仍存在；目标副本校验通过；`stream_*` 字段与目标对象一致；同一批次重跑不会产生重复副本或重复计费动作；副本不可用时原始播放回落成功。
- 费用报告能区分实时监控、延迟账单和项目估算，并记录查询时间与覆盖窗口。
- 复跑 `npm run smoke:media-delivery` 与 `npm run smoke:audio-stream-copy`；如需远程 DB/COS 写入测试，必须使用已批准的隔离范围。

### 实机验证

- Android Edge/Chrome 与鸿蒙浏览器分别播放迁移对象、未迁移对象和副本失败对象，确认副本成功时播放正常，失败时保留原始回落。
- 在慢网、重新进入页面和缓存命中/失效场景观察签名 URL、音频首帧和错误提示；打开应用不会触发历史资源批量写入。
- 检查重复封面仍可正常显示，未引用对象不会被用户界面伪装成可用媒体；费用验证以后台报告为准，不用手机显示替代实账。

### 停止/回滚条件

- 发现扫描、预览或测试路径有写入，立即停止并上报；不得以“临时对象”继续执行。
- 对象校验失败、源文件缺失、DB 引用不一致、签名 URL 失败、播放回落失败、RLS/权限异常或实际成本超批准上限时，停止当前批次。
- 目标副本出现问题时，优先将可空 `stream_*` 字段恢复为未启用状态；任何远程数据库写回、云对象处理或删除都必须遵循已批准的回滚方案，不自动删除原始或重复对象。
- 费用口径无法对齐时暂停扩批，只保留已批准且已验证的小批，等待账单/监控数据或用户决策。

### 完成定义

- 只读扫描、预览报告、用户批准、小批执行和费用验证五个阶段均有独立证据，顺序不可跳过。
- 小批范围、对象校验、数据库字段、旧客户端回落和实机播放均通过；原始对象未被删除或覆盖。
- 费用报告明确实账、监控、估算、时间窗口和异常；未能验证的指标被标记为未覆盖。
- Sol 独立验收后才可决定是否开启下一小批；一次小批通过不等于允许全量迁移。

- 不因排行需求合并 WebGL 正式实装分支或引入无关依赖。

### 数据/兼容边界

- PRD 必须明确本周、本月、全部时间的起止边界、时区、跨日/跨月行为、播放量定义、并列和空数据表现；实现沿用已确认的有效播放口径。
- 个人排行只读取当前用户自己的播放记录；私有歌曲只对本人显示，不能通过排序、缓存、预加载或错误态泄露给其他用户。
- 完整排行入口放在“我的”；首页只允许批准的轻量入口。历史数据缺失时显示诚实的空状态，不用估算或旧快照冒充实时结果。
- 优先复用现有统计来源和兼容入口；新增字段/接口必须可选，旧客户端无排行能力时继续正常播放、浏览和编辑。

### 实现任务

1. **PRD 阶段**：定义指标、事件有效性、时间窗口、数据源、RLS/隐私、入口、排序、缓存、分页/上限、加载/错误/空状态、性能预算和验收样例；同时区分个人排行、全站排行和创作者统计。
2. 由 Sol 组织 PRD 独立审阅并取得用户对口径和隐私的确认；未确认的字段和页面保持待讨论。
3. **个人排行第一期**：按已批准 PRD 实现“我的”页的个人排行和必要筛选；若 PRD 明确批准，再增加首页前 3–5 首轻量入口。
4. 加入账号隔离、时间边界、空/错/慢查询状态和可暂停的功能开关；任何远程 SQL 或数据库策略变更先走用户批准门。

### 自动验证

- PRD 样例覆盖本周/月/全部时间边界、时区、同一播放会话去重、空数据、并列和旧数据缺失。
- 隔离测试验证两个账号不能互读个人排行，私有歌曲不会进入公共结果；查询失败不会返回伪造的零值。
- 验证数据量上限、排序稳定性、重复请求/缓存一致性和无排行入口时旧客户端行为；必要时加入专用 smoke，不把未存在的脚本写成已通过。
- 运行 `npm run check` 和受影响的现有 smoke；涉及真实远程统计数据时必须使用批准的账号和范围。

### 实机验证

- Android 与鸿蒙浏览器登录两个测试账号，分别查看本人的周/月/全部排行，确认筛选、滚动、返回和空状态可用。
- 以私有歌曲和无播放记录账号验证不会串数据；切换账号、退出登录、刷新和弱网时不显示前一账号排行。
- 若已批准首页轻量入口，确认仅显示前 3–5 首并能回到正确歌曲；不改变资料库 Bento 视图。

### 停止/回滚条件

- 指标定义、时间边界或隐私边界仍有分歧时，停在 PRD 阶段，不以实现结果反推需求。
- 出现跨账号/私有数据泄露、计数与基线不一致、查询超时或远程写入范围超批准范围时，停止并撤下新入口。
- 回滚优先关闭新入口或功能开关，保留原有播放统计和数据；数据库回退、历史回填或删除必须另行获得用户批准。

### 完成定义

- 统计与排行 PRD 已经 Sol 独立审阅并得到用户确认，所有未决口径都有明确状态。
- 个人排行第一期的自动与实机证据通过，账号隔离、私有数据边界、窗口口径和错误态均可复核。
- 全站排行和创作者统计仅完成边界定义或保持待办，未被误报为本批已实现；旧客户端和资料库 Bento 视图无回归。

## 3. 记忆卡片独立 PRD 与实现

4. 为权限、幂等保存、刷新恢复、失败重试和旧数据兼容补齐自动证据；所有远程 DB 改动单独过批准门。

### 自动验证

- 验证播放器打开/关闭、歌曲切换、旧卡片加载和新卡片保存互不破坏；运行 `npm run check` 及受影响的 smoke。
- 若新增专用 smoke，必须把真实运行结果与仅静态检查区分，并说明远程数据是否为隔离样本。

### 实机验证

- 按批准 PRD 验证创建/编辑/删除、软键盘、长内容、弱网和失败重试；确认重复触控不会生成多份。
- 使用两个账号验证私有卡片不可见；确认卡片操作不会阻塞音频播放、播放器返回或底部导航。

### 停止/回滚条件

- 旧卡片无法读取、播放器被阻塞、卡片跨账号可见、数据迁移不可逆或内容校验会吞掉用户原文时，立即停止。
- 新实现异常时关闭新建/编辑入口或功能开关，保留旧卡片读取路径；不自行删除已经写入的远程数据。
- 任何数据库回滚、字段清理或批量转换都必须依据已批准的回滚方案执行，未批准则只报告影响。

### 完成定义

## 4. 上传跨关闭恢复、评论短期 SWR、历史失效资源等可靠性收尾

### 目标

收尾三类会让用户误以为数据丢失或内容不存在的可靠性问题：浏览器关闭后的上传草稿恢复、评论短期 stale-while-revalidate，以及历史失效音频/封面资源的诚实识别与回落。每项都以用户数据不串、不丢、不伪造为完成前提。

### 前置条件

- 第 0–3 批已完成；基线中的上传保存、评论分页/回复/失败重试和媒体回落行为可复测。
- 有隔离的上传样本、评论样本、旧媒体失效样本和两个测试账号；设备允许真实关闭/重开浏览器、切换网络和重新选择文件。
- 已明确草稿保留期限、文件权限/大小限制、评论 SWR 时效、错误显示规则和历史资源处理策略；不以浏览器能力不足为由默默声称“已恢复文件”。

### 明确不做

- 不把上传跨关闭恢复扩展成后台上传队列、跨设备同步或全量云端草稿系统，除非另行批准。
- 不把评论 SWR 扩展成永久离线数据库、通知中心或新互动功能；评论已有二期能力不重做。
- 不自动替换、删除、迁移或伪造历史失效资源，不把 404/403/签名过期显示成“暂无内容”。
- 不修改资料库 Bento 视图，不因可靠性收尾合并 WebGL 分支、重做播放器视觉或改动无关数据库结构。

### 数据/兼容边界

- 上传草稿必须按当前用户隔离；草稿元数据、上传阶段和文件可恢复性明确分层。浏览器无法持久化的文件句柄或原始字节必须提示重新选择，不伪造可恢复状态；过期草稿按明确规则处理。
- 评论 SWR key 至少区分用户、歌曲、排序、分页/游标和必要的权限上下文；缓存有短时 TTL，旧数据先展示但必须标注刷新状态，并在后台静默刷新。
- 评论发送、删除、点赞、歌曲切换、账号切换和权限变化要触发正确失效；网络失败不能把已有缓存改写成空评论，也不能把一首歌的缓存给另一首歌。
- 历史失效资源保留数据库 canonical 路径和原始诊断；允许刷新签名 URL或使用已有兜底，不允许用未验证对象、旧观点或虚假占位内容冒充真实媒体。
- 任何历史资源修复写回、COS 对象操作或远程 DB 更新都必须另过云资源/数据库用户批准门。

### 实现任务

1. **上传跨关闭恢复**：保存用户范围的草稿状态、编辑字段和恢复步骤；浏览器重开后恢复可恢复内容，无法恢复文件时明确要求重新选择，并防止重复保存/重复上传。
2. **评论短期 SWR**：按歌曲和查询维度建立有上限的短期缓存，切回歌曲先显示可用缓存再静默刷新；显示刷新中、过期、失败和重试状态，保持现有分页/回复/排序能力。
3. **历史失效资源**：区分签名过期、对象不存在、权限失败、格式不支持和网络失败；复用现有媒体回落/错误反馈，提供可重试或人工处理信号，不做静默云端修复。
4. 补齐边界日志和用户可理解的 inline/toast 状态，避免把可靠性修复变成新的阻塞式提示；按隔离样本逐项提交 Luna handoff。

### 自动验证

- 上传：自动化关闭/重启浏览器或模拟恢复边界，验证编辑字段、阶段、文件不可恢复提示、过期清理和重复提交保护；存储不可用时仍有明确失败路径。
- 评论：验证首次无缓存、命中新鲜缓存、命中过期缓存、后台刷新成功/失败、切歌、切账号、分页、排序、发送失败回滚和点赞/删除失效；不得出现跨歌曲或跨用户命中。
- 资源：用隔离的过期签名、404、403、格式错误和网络超时样本验证回落、重试、错误分类和不伪造空状态。
- 运行 `npm run check`、`npm run smoke:comments`、`npm run smoke:upload-metadata`、`npm run smoke:media-delivery`、`npm run smoke:audio-stream-copy` 及实际受影响 smoke；没有对应脚本的场景要标记为新增验证或未覆盖。

### 实机验证

- Android 与鸿蒙浏览器：选择文件、编辑后直接关闭并重新打开，验证可恢复字段和无法恢复文件时的重新选择流程；确认不会重复创建歌曲。
- 在手机上切换歌曲、离线/恢复网络、前后台切换评论区，确认旧评论先显示、后台刷新不清空、失败有重试，且不串到其他歌曲/账号。
- 打开历史失效音频和封面样本，确认用户看到的是明确回落/错误/重试状态，正常媒体仍可播放；不观察到自动批量迁移或云端写入。

### 停止/回滚条件

- 草稿丢失、重复上传、跨用户恢复、评论串歌/串账号、过期缓存覆盖新数据或错误态伪装成空内容时，停止对应子项。
- 文件句柄、浏览器存储或设备权限无法支持承诺的恢复语义时，降级为可验证的“恢复元数据 + 重新选择文件”，不得继续宣称完整恢复。
- 失效资源的自动修复需要远程写入时，停在诊断/预览，不自行修复、删除或替换对象。
- 回滚优先关闭新恢复/SWR/修复入口，保留基线的上传、评论和媒体回落；不清空用户已有草稿、评论或缓存以掩盖问题。

### 完成定义

- 上传关闭恢复、评论短期 SWR、历史失效资源三项均有各自自动和实机证据，失败与浏览器能力限制被如实记录。
- 草稿用户隔离、评论缓存隔离/失效、错误分类、媒体回落和重复提交保护通过；已有评论二期和新上传链路无回归。
- 任何云资源或远程 DB 修复动作仍保持待批准状态，未把诊断完成误报为资源已修复。
- Sol 对三项证据独立验收后，可靠性收尾批才可关闭。

## 5. 鸿蒙 WebView 壳、歌词、MV 作为后续独立决策门

### 目标

把鸿蒙 WebView 壳、歌词和 MV 分成三个互不捆绑的后续决策门，先确认价值、数据、设备、成本和兼容边界，再决定是否立项。当前阶段不实现其中任何一个，也不把“有方向”写成“已支持”。

### 前置条件

- 第 0–4 批完成；稳定 HTTPS 域名、设备矩阵、发布/回滚责任和成本预算可被审阅。
- 鸿蒙 WebView 壳需要确认全屏、安全区、返回手势、输入法、音频、上传文件选择、登录态和系统权限；正式方案不得依赖临时 `trycloudflare.com` 地址。
- 歌词需要确认只支持用户提供的本地/上传/内嵌内容、解析格式、时间轴质量和无歌词状态；不得默认接入联网歌词服务。
- MV 需要确认可接受的视频格式、大小/时长、COS 存储与下行成本、私有访问和移动端全屏行为；不得默认抓取或接入外部 MV。

### 明确不做

- 不在本阶段新建 HarmonyOS/ArkTS 工程，不修改 PWA、路由、上传、登录或部署配置，不发布 WebView 壳。
- 不实现联网歌词、歌词社区、歌词评论锚点或 Apple Music 动效；不因歌词方向改动现有评论数据。
- 不实现 MV 上传/转码/播放，不接入外部视频源，不为 MV 预先修改数据库或 COS。
- 不合并 `codex/webgl-liquid-glass-app-integration`；WebGL 正式实装仍由独立分支/独立决策处理。资料库 Bento 视图继续不改。

### 数据/兼容边界

- WebView 壳若获批，必须是独立宿主，加载稳定 HTTPS 的现有 Web 应用；PWA、桌面浏览器和旧客户端行为不因壳方案被替换或强制升级。
- 歌词只消费已批准的本地、上传或内嵌数据；无歌词、解析失败和时间轴不完整时显示诚实空状态/降级，不用联网结果或旧缓存填充。
- MV 只能是歌曲的可选资源；无 MV 时不显示入口，有 MV 时必须遵守歌曲/用户可见性与签名访问边界。任何新增存储字段保持可选，旧歌曲继续播放。
- 三个方向的资源、权限、费用、日志和回滚分别记录；一个方向的批准不代表另外两个方向获批。

### 实现任务

1. 为鸿蒙 WebView 壳准备独立决策包：稳定域名、系统能力、权限、安全区、返回、输入法、音频/上传、登录态、设备兼容、发布和回滚。
2. 为歌词准备独立决策包：支持格式、数据来源、解析契约、时间轴、无歌词/错误态、存储和隐私；明确不依赖联网歌词。
3. 为 MV 准备独立决策包：资源模型、上传限制、编码/播放能力、COS 成本、签名访问、私有内容、移动端全屏和失败回落。
4. Sol 分别审阅三份决策包并取得用户批准；只有某个方向单独获批后，才能产生新的 Luna 开发 handoff、文件白名单和验收矩阵。

### 自动验证

- 当前阶段只验证决策包完整性、相互独立性、兼容/权限/成本/回滚字段齐全，以及仓库没有因为该方向产生业务代码、配置、SQL 或依赖改动。
- 不运行不存在的 WebView、歌词或 MV smoke，不把静态文档审阅写成设备支持；若未来批准原型，必须新增对应自动验证并单独报告。
- 每个方向的后续自动验证至少要覆盖旧 Web 客户端兼容、权限隔离、失败回落和无资源状态；远程 DB/COS 试验仍需用户批准。

### 实机验证

- 本批不宣称已经完成鸿蒙 WebView、歌词或 MV 实机验证；设备验证是各自决策门批准后的必需条件。
- WebView 方向后续至少要在目标鸿蒙设备检查桌面入口、无地址栏、状态栏/安全区、返回、输入法、音频、上传和登录态。
- 歌词方向后续要在真实本地/上传/内嵌样本检查解析、跟随进度、无歌词和弱网；MV 方向后续要检查真实移动端播放、全屏、私有访问、失败回落和流量成本。

### 停止/回滚条件

- 稳定域名、设备能力、隐私、版权/来源、成本或发布回滚尚未明确时，停在决策包，不写代码。
- 任一方向要求改动另一个方向的数据模型、PWA 核心流程或 Bento 视图时，拆回独立决策，等待 Sol 和用户重新确认。
- 原型若出现音频/上传/登录回归、私有资源泄露、不可接受流量成本或无法回滚，关闭原型入口并回到决策状态；不自行保留半成品作为正式能力。

### 完成定义

- 三个方向均有独立的范围、前置、数据/兼容、设备、成本、隐私和回滚决策；每个方向明确“批准/延后/拒绝”，而不是笼统地标记为“后续开发”。
- 当前阶段的完成只意味着决策门准备完毕，不意味着鸿蒙 WebView、歌词或 MV 已实现或已通过实机验收。
- 任一方向获批后，必须生成新的边界清晰 handoff；Sol 继续负责规划和独立验收，Luna 只执行获批范围内的任务。

## 总体暂停、恢复与汇报格式

- 每批结束时保留：基线/版本、实际改动、自动验证命令及结果、实机设备与结果、未覆盖项、失败风险、批准状态和下一批前置条件。
- 可以在任意“只读扫描”“预览”“PRD 审阅”“用户批准”“小批执行”“独立验收”门暂停；恢复时先复核数据、账号、成本和基线是否仍有效，再继续同一门，不默认跳到下一批。
- 远程备份、远程数据库、COS 或其他云资源只要有一个批准项缺失，就保持暂停；Sol 的独立验收只能确认证据，不能替用户授权云端写操作。
- 最终汇报只陈述本轮实际新增文件、实际运行的验证和未决批准门；计划中的实现、历史文档中的完成记录和未执行的实机测试不得写成当前已完成。
